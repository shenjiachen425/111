# 02a 项目背景与商业目标

> 编号：02a ｜ 类别：项目基本简报（共 4 份）｜ 来源：拾光连锁会员权益智能体 MVP 项目

## 1. 项目方与业务域
- **项目方**：拾光连锁（零售连锁品牌），本期聚焦 **会员权益域**（优惠券、折扣、抵用、兑换等权益的查询、核销与售后）。
- **本期形态**：最小可行产品（MVP）——员工端 + 管理端，用于替代/辅助门店现场的人工权益核验。

## 2. 业务背景与痛点（来自六人访谈，已确认）
会员权益在门店现场长期依赖人工处理，存在以下结构性问题：

| 编号 | 痛点 | 访谈确认情况 |
|---|---|---|
| PT-1 | 权益核验慢，收银现场反复致电运营 | 单次核验约 **3 分钟**（访谈确认），目标降至 **40 秒** |
| PT-2 | 投诉量高，售后环节来回确认 | 月投诉约 **240 件**（访谈确认），目标降至 **100 件/月** |
| PT-3 | 口径不一：同一张券小程序与门店解释不同 | 〔待验证〕典型事例 P2 |
| PT-4 | 收银依赖人工，无法自助核验 | 〔待验证〕典型事例 P1 |
| PT-5 | 售后同问题在环节间反复流转 | 〔待验证〕典型事例 P3 |
| PT-6 | 规则无统一版本，变更不可追溯 | 知识库缺失版本化 |
| PT-7 | 异常无升级通道，现场自行放行 | 缺转人工/审计机制 |

> 说明：投诉 240→100 件/月、核验 3 分钟→40 秒为**访谈确认的目标值**，在系统中作为验收基线采集，非系统已自动达成的指标。

## 3. 项目目标
1. **提效**：把权益核验从人工致电运营（约 3 分钟）压缩到员工端自助核验（目标 40 秒）。
2. **降诉**：统一权益口径、明确规则来源，目标将月投诉从 240 件降至 100 件。
3. **统一口径**：以版本化知识库为唯一事实源，消除"小程序 vs 门店"解释差异。
4. **可审计**：每一次查询、核销、转人工、发版均可追溯。
5. **可控升级**：退货类等高风险场景强制转人工，异常绝不自动放行。

## 4. 商业价值
- **直接**：减少收银台等待、降低运营被致电打扰、压缩售后流转。
- **间接**：提升会员满意度与复购，沉淀可复用的权益知识资产。
- **合规**：版本化 + 审计链满足规则变更的合规留痕要求。
